# 示例：实现抽签

在 [`README.md`](./README.md) 跑通 **hello** 之后，用同样方式做 **带可视化页面** 的小插件：在会话里点按钮打开面板，而不是只靠模型调工具。开始前、排错按 README 的 **第 2～3 步**；打包按本文 **第 4 步**（三种方式与 README 相同）。

| 项 | 说明 |
| --- | --- |
| 插件目录 | `plugins/dsh-lucky-draw-ui`（树外；Host + Client） |
| 包名 | `@nangeagi/dsh-lucky-draw-ui`，版本 `0.0.1` |
| 页面 | 浮层：一行一个选项；「抽一下」；结果大字 + 一句短鼓励语；可复制或写入输入框 |
| 端 | Desktop / Web 同一 Client |

---

## 第 1 步：一次说清并完成插件

在 **创造模式** 会话中发送：

```
我想在当前工作区做「幸运抽签」插件，带可视化页面（Host + Client 树外插件），可装到 web、desktop 等 profile。

插件目录：plugins/dsh-lucky-draw-ui

可视化（必做）：
1. 会话入口如「抽签」，打开浮层。
2. 上方多行输入，一行一个选项（预填：咖啡 / 奶茶 / 白开水 / 继续敲代码）；中间大按钮「抽一下」；下方用较大字号显示抽中项，并加一句简短、轻松的鼓励语。
3. 提供「复制结果」或「写入输入框（append，不自动发送）」至少一种。
4. 选项为空时按钮禁用或在页面内提示。
5. Harness token 做面板 chrome，不挡 composer；inspect 选 Slot。

Host（可选）：页面状态只在前端时 Host 最小化；若记住上次选项，存工作区 .dsh/lucky-draw-ui/，由 Host RPC 读写。

可选：再注册模型工具 lucky_draw，参数 items 为逗号分隔字符串，逻辑与页面一致。验收以页面为准。

验收（目视）：
- 见「抽签」入口；打开后点「抽一下」，结果区有变化；若做了写入输入框，composer 里能看到对应文字。

请 inspect、实现、安装到当前 profile；给目视验收步骤。
```

若 Agent 请求授权（改 profile、安装插件），在当前客户端里按提示批准。

## 第 2 步：验收（看页面）

新建 **标准模式** 会话，按 Agent 给的步骤目视操作：

1. 会话里能看到 **抽签** 入口。
2. 打开后有选项输入、**抽一下**、结果区。
3. 连续点多次「抽一下」，不同选项都会出现。
4. 「写入输入框」或「复制」可用。
5. **设置 → 插件** 中插件为已启用。

## 第 3 步：失败时只修当前问题

```
dsh-lucky-draw-ui 的可视化还没验收通过。现象是：（粘贴报错、空白页、插件状态）

请只解决这一个现象，不要加新功能。修完后告诉我：改了什么、要不要重启客户端、目视验收步骤是否变化。
```

## 第 4 步：打包发布

当前 profile 目视验收通过后，三选一交付。目录为 `plugins/dsh-lucky-draw-ui`，包名为 `@nangeagi/dsh-lucky-draw-ui`，版本 `0.0.1`。

命令前缀：Web（npm）用 `npx @deepseek-ai/dsh`，源码仓用 `pnpm dsh`。`--profile`：Web 为 `web`，Desktop 为 `desktop`。下面命令以 `npx`、`web` 为例。

对方能运行 `dsh` 即可。装完重启对应客户端，按第 2 步目视验证。卸载：

```sh
npx @deepseek-ai/dsh plugin --profile web remove @nangeagi/dsh-lucky-draw-ui
```

### tarball

在创造模式发送：

```
dsh-lucky-draw-ui 已在当前 profile 验收通过。请直接打成 tarball，使它可被 dsh plugin add 安装，不要加功能。

插件目录：plugins/dsh-lucky-draw-ui

package.json（必做）：
1. name 写为 @nangeagi/dsh-lucky-draw-ui，version 写为 0.0.1。
2. private 保持 true。
3. dsh.bundle.patch 指向 ./cordis.patch.yml。
4. files 包含构建产物、cordis.patch.yml 和 Client 产物。
5. peerDependencies 改为 semver，去掉 workspace:^。

cordis.patch.yml（必做）：
1. 入口指向 lib 里的 js，不指向 src/。

打包（必做）：
1. 在插件目录执行 build，确认产物存在。
2. 包内不含密钥和 .npmrc。
3. 在插件目录执行 npm pack，生成 tarball。

验收：
- 告诉我包名、版本，以及 tarball 的实际路径和文件名。

请直接改文件、build，并执行 npm pack。
```

Agent 会在插件目录生成 tarball。接着在本机复验：

```sh
npx @deepseek-ai/dsh plugin --profile web remove @nangeagi/dsh-lucky-draw-ui
npx @deepseek-ai/dsh plugin --profile web add ./plugins/dsh-lucky-draw-ui/nangeagi-dsh-lucky-draw-ui-0.0.1.tgz
```

重启当前端，新建标准模式会话，按第 2 步目视验收。**设置 → 插件** 为已启用即通过。

要装到另一个端，把 `--profile` 换成 `desktop`（或 `headless`），add 同一个 tarball，只启动那个端再验一次。页面在目标端也要目视入口和浮层。工作区里的 `.dsh/lucky-draw-ui/` 不在包内，换机器时单独拷贝工作区。

`npm pack` 会生成 `nangeagi-dsh-lucky-draw-ui-0.0.1.tgz`。把这个文件发给对方，在文件所在目录执行：

```sh
npx @deepseek-ai/dsh plugin --profile web add ./nangeagi-dsh-lucky-draw-ui-0.0.1.tgz
```

```
dsh-lucky-draw-ui 已在当前 profile 验收通过。请只做 npm 发布准备，把它改成可用包名 dsh plugin add 安装的包，不要加功能。

插件目录：plugins/dsh-lucky-draw-ui

package.json（必做）：
1. name 写为 @nangeagi/dsh-lucky-draw-ui，并用 npm view 确认未被占用。
2. version：未发布过用 0.0.1，已发布则递增。
3. private 改为 false。
4. dsh.bundle.patch 指向 ./cordis.patch.yml。
5. files 包含构建产物、cordis.patch.yml 和 Client 产物。
6. peerDependencies 改为 semver，去掉 workspace:^。

cordis.patch.yml（必做）：
1. 入口指向 lib 里的 js，不指向 src/。

构建（必做）：
1. 执行 build，确认产物存在。
2. 包内不含密钥，不要把 npm token 写进仓库。

验收：
- 告诉我最终包名、版本，以及对方的安装命令。

请直接改文件并 build。不要执行 npm publish。
```

Agent 改完后，在 [npmjs.com](https://www.npmjs.com) 生成 Publish 权限的 Access Token，写入用户主目录的 `~/.npmrc`（macOS 即 `/Users/你的用户名/.npmrc`）。不要放在插件目录里，也不要提交到 git。在插件目录执行 `npm publish` 时会自动读到这份配置：

```
//registry.npmjs.org/:_authToken=你的token
```

```sh
cd plugins/dsh-lucky-draw-ui
npm publish --access public
```

对方安装：

```sh
npx @deepseek-ai/dsh plugin --profile web add @nangeagi/dsh-lucky-draw-ui
```
