# 示例：实现配色灵感

在 [`README.md`](./README.md) 跑通 **hello** 之后，用同样方式做 **带可视化页面** 的配色面板。开始前、排错按 README 的 **第 2～3 步**；打包按本文 **第 4 步**（三种方式与 README 相同）。

| 项 | 说明 |
| --- | --- |
| 插件目录 | `plugins/dsh-palette-ui`（树外；Host + Client） |
| 包名 | `@nangeagi/dsh-palette-ui`，版本 `0.0.1` |
| 页面 | 浮层：一次 3 组配色卡片；「换一组」；点击复制 CSS 变量 |
| 端 | Desktop / Web 同一 Client |

---

## 第 1 步：一次说清并完成插件

在 **创造模式** 会话中发送：

```
我想在当前工作区做「配色灵感」插件，带可视化页面（Host + Client 树外插件），可装到 web、desktop 等 profile。

插件目录：plugins/dsh-palette-ui

可视化（必做）：
1. 会话入口如「配色」，打开浮层。
2. 同时展示 3 组配色卡片：每组有色块预览（至少 3 个色块）、组名如「方案 A/B/C」。
3. 按钮「换一组」重新随机 3 组；点击某一卡片复制该组 CSS 变量片段到剪贴板（含 --palette-primary 等语义化命名），并 toast「已复制」。
4. 配色尽量协调；背景与正文色对比度不要太差（简单检查即可）。
5. Harness token 做面板 chrome，卡片内可用生成的颜色；inspect 选 Slot。

Host（可选）：提供 generatePalettes(count) RPC；若纯前端随机则 Host 最小化。

验收（目视）：
- 见入口；打开见 3 张卡片；换一组颜色变；点卡片复制后我能粘贴出 CSS 变量文本。

请 inspect、实现、安装到当前 profile；给目视验收步骤。
```

若 Agent 请求授权（改 profile、安装插件），在当前客户端里按提示批准。

## 第 2 步：验收（看页面）

新建 **标准模式** 会话，按 Agent 给的步骤目视操作：

1. 入口可见，打开后三组色块同时可见。
2. 「换一组」后颜色变化。
3. 点击卡片复制，粘贴能看到 CSS 变量，并有「已复制」提示。
4. **设置 → 插件** 中插件为已启用。

## 第 3 步：失败时只修当前问题

```
dsh-palette-ui 的可视化还没验收通过。现象是：（粘贴报错、空白页、复制失败）

请只解决这一个现象，不要加新功能。修完后告诉我：改了什么、要不要重启客户端、目视验收步骤是否变化。
```

## 第 4 步：打包发布

当前 profile 目视验收通过后，三选一交付。目录为 `plugins/dsh-palette-ui`，包名为 `@nangeagi/dsh-palette-ui`，版本 `0.0.1`。

命令前缀：Web（npm）用 `npx @deepseek-ai/dsh`，源码仓用 `pnpm dsh`。`--profile`：Web 为 `web`，Desktop 为 `desktop`。下面命令以 `npx`、`web` 为例。

对方能运行 `dsh` 即可。装完重启对应客户端，按第 2 步目视验证。卸载：

```sh
npx @deepseek-ai/dsh plugin --profile web remove @nangeagi/dsh-palette-ui
```

### tarball

在创造模式发送：

```
dsh-palette-ui 已在当前 profile 验收通过。请直接打成 tarball，使它可被 dsh plugin add 安装，不要加功能。

插件目录：plugins/dsh-palette-ui

package.json（必做）：
1. name 写为 @nangeagi/dsh-palette-ui，version 写为 0.0.1。
2. private 保持 true。
3. dsh.bundle.patch 指向 ./cordis.patch.yml。
4. files 包含构建产物、cordis.patch.yml 和 Client 产物。
5. peerDependencies 改为 semver，去掉 workspace:^。

cordis.patch.yml（必做）：
1. 入口指向 lib 里的 js，不指向 src/。

打包（必做）：
1. 在插件目录执行 build，确认产物存在。
2. 包内不含密钥和 .npmrc。
3. 在插件目录执行 npm pack，生成 tarball。

验收：
- 告诉我包名、版本，以及 tarball 的实际路径和文件名。

请直接改文件、build，并执行 npm pack。
```

Agent 会在插件目录生成 tarball。接着在本机复验：

```sh
npx @deepseek-ai/dsh plugin --profile web remove @nangeagi/dsh-palette-ui
npx @deepseek-ai/dsh plugin --profile web add ./plugins/dsh-palette-ui/nangeagi-dsh-palette-ui-0.0.1.tgz
```

重启当前端，新建标准模式会话，按第 2 步目视验收。**设置 → 插件** 为已启用即通过。

要装到另一个端，把 `--profile` 换成 `desktop`（或 `headless`），add 同一个 tarball，只启动那个端再验一次。页面在目标端也要目视入口，并再测一次复制。

`npm pack` 会生成 `nangeagi-dsh-palette-ui-0.0.1.tgz`。把这个文件发给对方，在文件所在目录执行：

```sh
npx @deepseek-ai/dsh plugin --profile web add ./nangeagi-dsh-palette-ui-0.0.1.tgz
```

### npm

在创造模式发送：

```
dsh-palette-ui 已在当前 profile 验收通过。请只做 npm 发布准备，把它改成可用包名 dsh plugin add 安装的包，不要加功能。

插件目录：plugins/dsh-palette-ui

package.json（必做）：
1. name 写为 @nangeagi/dsh-palette-ui，并用 npm view 确认未被占用。
2. version：未发布过用 0.0.1，已发布则递增。
3. private 改为 false。
4. dsh.bundle.patch 指向 ./cordis.patch.yml。
5. files 包含构建产物、cordis.patch.yml 和 Client 产物。
6. peerDependencies 改为 semver，去掉 workspace:^。

cordis.patch.yml（必做）：
1. 入口指向 lib 里的 js，不指向 src/。

构建（必做）：
1. 执行 build，确认产物存在。
2. 包内不含密钥，不要把 npm token 写进仓库。

验收：
- 告诉我最终包名、版本，以及对方的安装命令。

请直接改文件并 build。不要执行 npm publish。
```

Agent 改完后，在 [npmjs.com](https://www.npmjs.com) 生成 Publish 权限的 Access Token，写入用户主目录的 `~/.npmrc`（macOS 即 `/Users/你的用户名/.npmrc`）。不要放在插件目录里，也不要提交到 git。在插件目录执行 `npm publish` 时会自动读到这份配置：

```
//registry.npmjs.org/:_authToken=你的token
```

```sh
cd plugins/dsh-palette-ui
npm publish --access public
```

对方安装：

```sh
npx @deepseek-ai/dsh plugin --profile web add @nangeagi/dsh-palette-ui
```
