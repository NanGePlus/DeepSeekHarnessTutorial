# 示例：明星周边开售提醒

在 [`README.md`](./README.md) 跑通 **hello** 之后，用同样方式做 **带可视化页面** 的开售提醒：在工作区维护开售事件，用倒计时在提前时刻和正点提醒，并打开官方购买链接。开始前、排错按 README 的 **第 2～3 步**；打包按本文 **第 4 步**（三种方式与 README 相同）。

| 项 | 说明 |
| --- | --- |
| 插件目录 | `plugins/dsh-merch-reminder-ui`（树外；Host + Client） |
| 包名 | `@nangeagi/dsh-merch-reminder-ui`，版本 `0.0.1` |
| 页面 | 浮层：即将开售、全部订阅、日历或时间线 |
| 数据 | 工作区 `.dsh/merch-reminder/events.json` |
| 端 | Desktop / Web 同一 Client |

---

## 第 1 步：一次说清并完成插件

在 **创造模式** 会话中发送：

```
我想在当前工作区做「明星周边开售提醒」插件，带可视化页面（Host + Client 树外插件），可装到 web、desktop 等 profile。

插件目录：plugins/dsh-merch-reminder-ui

可视化（必做）：
1. 会话入口「开售提醒」，打开浮层。未选工作区时入口禁用并提示。
2. 「即将开售」按倒计时排序；「全部订阅」列表；「日历/时间线」按日期浏览。
3. 新增、编辑、删除，以及启用开关。字段：明星或系列名、周边名称、开售时间（含时区，默认 Asia/Shanghai）、官方购买链接、备注。
4. 卡片显示距离开售还有多久。提前提醒默认 30 分钟、10 分钟，可再加 1 天；同一提前量只提醒一次。到点有页面提示，「打开链接」在浏览器打开官方 URL。
5. Harness token 做面板 chrome，不挡 composer；inspect 选 Slot。

Host（必做）：
1. 读写 .dsh/merch-reminder/events.json。
2. RPC：list、save、delete、getUpcoming。
3. 按本地时间对比开售时间与提前提醒点，触发后写入 reminded 标记。

可选：模型工具 merch_reminder_upcoming，返回未来 7 天内事件摘要。验收以页面为准。

验收（目视）：
- 选好工作区见入口；新建开售时间为「当前 + 12 分钟」的 demo，提前提醒 10 分钟与 2 分钟。
- 倒计时走动；到点有页面提示；「打开链接」可用。

请 inspect、实现、安装到当前 profile；说明数据路径和 12 分钟 demo 的目视验收步骤。
```

若 Agent 请求授权（改 profile、安装插件），在当前客户端里按提示批准。

## 第 2 步：验收（看页面）

新建 **标准模式** 会话，按 Agent 给的步骤目视操作：

1. 无工作区时入口不可用，或提示明确。
2. 增删改事件后，数据在 `.dsh/merch-reminder/`，刷新仍在。
3. 倒计时走动，「即将开售」排序正确。
4. 提前提醒与正点提醒各出现一次。
5. 「打开链接」可用；**设置 → 插件** 中插件为已启用。

## 第 3 步：失败时只修当前问题

```
dsh-merch-reminder-ui 的可视化还没验收通过。现象是：（粘贴报错、空白页、倒计时不准）

请只解决这一个现象，不要加新功能。修完后告诉我：改了什么、要不要重启客户端、目视验收步骤是否变化。
```

## 第 4 步：打包发布

当前 profile 目视验收通过后，三选一交付。目录为 `plugins/dsh-merch-reminder-ui`，包名为 `@nangeagi/dsh-merch-reminder-ui`，版本 `0.0.1`。

命令前缀：Web（npm）用 `npx @deepseek-ai/dsh`，源码仓用 `pnpm dsh`。`--profile`：Web 为 `web`，Desktop 为 `desktop`。下面命令以 `npx`、`web` 为例。

对方能运行 `dsh` 即可。装完重启对应客户端，按第 2 步目视验证。卸载：

```sh
npx @deepseek-ai/dsh plugin --profile web remove @nangeagi/dsh-merch-reminder-ui
```

### tarball

在创造模式发送：

```
dsh-merch-reminder-ui 已在当前 profile 验收通过。请直接打成 tarball，使它可被 dsh plugin add 安装，不要加功能。

插件目录：plugins/dsh-merch-reminder-ui

package.json（必做）：
1. name 写为 @nangeagi/dsh-merch-reminder-ui，version 写为 0.0.1。

3. dsh.bundle.patch 指向 ./cordis.patch.yml。
4. files 包含构建产物、cordis.patch.yml 和 Client 产物。
5. peerDependencies 改为 semver，去掉 workspace:^。

cordis.patch.yml（必做）：
1. 入口指向 lib 里的 js，不指向 src/。

打包（必做）：
1. 在插件目录执行 build，确认产物存在。
2. 包内不含密钥和 .npmrc。
3. 在插件目录执行 npm pack，生成 tarball。

验收：
- 告诉我包名、版本，以及 tarball 的实际路径和文件名。

请直接改文件、build，并执行 npm pack。
```

Agent 会在插件目录生成 tarball。接着在本机复验：

```sh
npx @deepseek-ai/dsh plugin --profile web remove @nangeagi/dsh-merch-reminder-ui
npx @deepseek-ai/dsh plugin --profile web add ./plugins/dsh-merch-reminder-ui/nangeagi-dsh-merch-reminder-ui-0.0.1.tgz
```

重启当前端，新建标准模式会话，按第 2 步目视验收。**设置 → 插件** 为已启用即通过。

要装到另一个端，把 `--profile` 换成 `desktop`（或 `headless`），add 同一个 tarball，只启动那个端再验一次。页面在目标端也要目视入口和倒计时。工作区里的 `.dsh/merch-reminder/` 不在包内，换机器时单独拷贝工作区。

`npm pack` 会生成 `nangeagi-dsh-merch-reminder-ui-0.0.1.tgz`。把这个文件发给对方，在文件所在目录执行：

```sh
npx @deepseek-ai/dsh plugin --profile web add ./nangeagi-dsh-merch-reminder-ui-0.0.1.tgz
```

```
//registry.npmjs.org/:_authToken=你的token
```
